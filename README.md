# Разбор входящих заявок

Менеджер вставляет обращение и получает тему и черновик, который можно проверить перед отправкой. Если модель ошиблась, исходная заявка остаётся на экране для ручного разбора.

## Запуск

Из корня проекта с Node.js 20 или новее выполните команду ниже. Для сервера и тестов API достаточно самого Node.js. Имитатор работает локально.

```sh
node server.mjs
```

Откройте [страницу заявок](http://127.0.0.1:3000). Другой порт можно задать переменной `PORT`.

## Тесты

Тесты API сами поднимают сервер на свободном порту. Они проверяют HTTP-коды и полное тело ответа для некорректного ввода, трёх допустимых тем и всех пяти режимов сбоя.

```sh
node --test
```

Для браузерного теста установите Playwright и Chromium. Он открывает настоящую страницу, получает черновик, вызывает таймаут и проверяет, что старые тема и текст удалены, а исходная заявка доступна. Затем проверяет пустой ввод и повторный успешный разбор.

```sh
npm ci
npx playwright install chromium
npm run test:ui
```

## Контракт API

`POST /api/triage` принимает JSON, например `{"text":"Когда будет доставка?"}`.

| Условие | HTTP | Ответ |
| --- | --- | --- |
| Невалидный JSON, поле `text` отсутствует, содержит другой тип или пусто после `trim()` | 400 | `{"status":"invalid_input"}` |
| Тема и черновик прошли проверку | 200 | `{"status":"ready","topic":"delivery","draft":"Спасибо за обращение. Уточним детали заявки."}` |
| Таймаут, ошибка имитатора или некорректный результат | 200 | `{"status":"manual_review","topic":null,"draft":null}` |

В `app.mjs` функция `triage` передаёт имитатору сигнал отмены с дедлайном 300 мс. Затем она разбирает JSON и допускает в ответ только тему из набора `delivery`, `pricing`, `other` и непустой строковый черновик. Страница удаляет предыдущий результат при изменении заявки и перед новым запросом.

## Проверка на странице

1. Введите «Когда будет доставка?» и нажмите «Разобрать заявку». Появятся тема «Доставка» и черновик.
2. Добавьте к заявке `[timeout]` и повторите разбор. На экране останется введённый текст и появится сообщение «Нужен ручной разбор».
3. Аналогично можно проверить `[error]`, `[bad-json]`, `[bad-topic]` и `[empty-draft]`. Уберите метку и повторите разбор, чтобы снова получить черновик.

## Польза для менеджера

Готовый черновик экономит время на типовых заявках, а при сбое менеджер сразу видит, что ответ нужно написать вручную. Эффект можно измерить, сравнив медианное время от открытия заявки до готового к отправке ответа на сопоставимых обращениях с помощником и без него.
